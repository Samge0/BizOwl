# BizOwl 文档导出

所有真实文件交付意图都先进入本技能。本技能是文档导出的总入口，负责判断导出内容、目标格式和执行路线。

## 本技能执行流程

执行时固定按下面顺序：

1. 确定文件交付内容
2. 判定目标文档格式
3. 选择文档交付执行路线
   - 如果需要专业版导出，则基于目标文档格式分别转交给各自的专业SKILL完成后续流程
   - 如果需要快速导出，则直接使用本技能内部快速导出能力完成文档导出

若用户要求“查一下某信息并生成文件”，不要跳过本技能；先完成必要查询和正文整理，再继续执行导出流程。

## 目标文档格式判定

格式判定优先级：

1. 用户明确指定格式。
2. 知识库或业务场景预设格式。
3. 基于业务意图推断。

默认格式：

| 业务意图                 | 典型线索                                                               | 默认格式      |
| ------------------------ | ---------------------------------------------------------------------- | ------------- |
| 阅读 / 存证意图          | 尽调报告、信用报告、裁判文书；常伴随“发客户”“看看背景”                 | PDF           |
| 编辑 / 起草意图          | 合同草稿、意见书、简报；常伴随“起草”“帮我写”                           | DOCX          |
| 分析 / 筛选意图          | 名单、财务数据、招投标批量数据；常伴随“拉个表”“汇总数据”               | XLSX          |
| 会议 / 演示意图          | 客户拜访方案、高管汇报摘要、商业竞品分析；常伴随“给领导汇报”“做个演示” | PPTX          |
| HTML / 网页意图          | HTML、网页报告、单文件网页                                             | HTML          |
| 无法明确判定的纯文本内容 | 无明确业务意图                                                         | Markdown 文件 |

## 文档交付执行路线

### 判定条件:

1. 目标格式为 HTML / 网页报告 / 单文件网页：
   转 `html-generator`，不进入快速版 / 专业版二分。
2. 目标格式为 XLSX / CSV，且明细正文长度过长、不适合一次性放入 `content`：
   走“大批量分页明细受控导出流程”，不读取 `xlsx` skill，不调用 `document_export` 承载全量 `content`。
3. 目标格式为 PPT / PPTX:
   默认走专业版，转 `pptx` skill。
4. 目标格式为 PDF / DOCX / XLSX / CSV：
   若用户明确要求封面、目录、排版优化、视觉优化、正式汇报、发客户、对外提交、复杂图表，或用户明确不满意普通导出版式，并要求重新排版、视觉优化或正式成品质量，走专业版。
5. 其余非 HTML 场景：
   走快速版

### 专业版文档转交目标 skill

| 目标文档格式      | SKILL            |
| ----------------- | ---------------- |
| PDF               | `pdf`            |
| DOC / DOCX / Word | `docx`           |
| XLSX / CSV        | `xlsx`           |
| PPTX / PPT        | `pptx`           |
| HTML              | `html-generator` |

## 约束

### 内容约束

- 导出内容只能来自本次确认的业务正文、名单、表格、摘要、演示材料或用户明确提供的内容。
- 导出主体必须与用户本次点名的企业、人员、项目、名单或材料一致；主体不一致时停止导出并重新整理或澄清。
- 不要从历史任务、其他企业材料、文件名、导出成功提示或工具记录里拼接导出源。
- 不要把文件路径、导出成功提示、交付文件清单、文件卡片描述或工具调用结果当作文档正文。
- 若用户提供的文本只有文件路径或导出成功提示，没有业务正文，应提示用户提供要导出的业务正文。
- 若文件中需要展示查询时间、数据更新时间、截止日期或报告日期，必须沿用已核验字段；没有证据时不得补写日期。
- `document_export` 的 `mode="current"` 仅适用于桌面托管会话；原生 IM/channel 会话必须使用 `mode="content"` 并传入最终正文。

### 文件命名与保护

- 默认情况下，新生成的最终文档使用“标题或指定基础名 + `YYYYMMDD-HHMMSS`”的文件名；时间戳由受控导出器统一追加。
- `outputFileName` 只传简短基础名，不要传目录或时间戳；扩展名可以省略。工具返回的实际文件路径才是最终交付路径。
- 同一秒生成同名文档时，导出器会自动追加 `-2`、`-3` 等序号并保留旧文件。
- 除非用户明确要求覆盖某个指定的已有文件，否则不得使用 `write`、`exec`、`cp`、`mv` 或其它工具覆盖、删除、替换此前生成的文档，也不得把新文件复制回不带时间戳的旧文件名。覆盖目标必须由用户明确点名，不能由模型根据文件名或上下文猜测。
- 用户明确要求覆盖时，仍先通过受控导出器生成带时间戳的新文件；确认用户点名的目标路径后，才可用新文件覆盖该目标，不得连带修改其它历史文件。
- 若工具提示已避让同名文件，必须接受工具返回的新路径并继续交付，不要尝试恢复成旧文件名。

### 快速版约束

- 快速版只用于普通版式交付；不要读取 `pdf` / `docx` / `xlsx` / `pptx` 等专业版 skill。
- 快速版由本技能受控导出能力执行；不要自行运行 `scripts/compile_markdown_document.py`、`python`、`node`、`soffice`、`pandoc` 或 `playwright`。
- 不要调用 `document_export(format="html")`。

### 大批量分页明细受控导出流程

当目标格式为 XLSX / CSV，且明细正文长度过长、不适合一次性放入 `content` 时，必须使用本流程；不要改走专业版，不要读取 `xlsx` skill，不要调用 `document_export` 承载全量 `content`，也不要编写 Excel / CSV 生成脚本。

若明细正文可以稳定一次性整理成 Markdown 表格 / 正文放入 `content`，仍使用快速版 `document_export(mode="content")`，不要使用本流程。

固定流程：

1. 若还没有用户确认，先询问：`结果较多，我将完整获取并导出为文件，可能耗时。是否继续？`
2. 用户确认后，调用 `qcc_export_paginated_table`。
3. 入参只声明：已确认的数据源 MCP `url` / `name`、查询条件 `subParams`、分页参数约定、导出字段 `columns`、目标格式和文件名。
4. 不要手动分页，不要把全量记录放入上下文，不要写 CSV 分片，不要写 Python / Node / shell 脚本。
5. 工具返回成功后，交付最终 XLSX / CSV 文件路径、数据行数和主要字段。

`Search_general_search_get` 这类高级搜索明细的常用入参：

- `pagination.pageIndexParam`: `pageIndex`
- `pagination.pageSizeParam`: `pageSize`
- `pagination.pageSize`: `50`
- `pagination.recordsPath`: `记录`
- `pagination.totalPath`: `分页.total`
- `pagination.returnedPath`: `分页.returned`
- `pagination.responseSessionIdPath`: `sessionId`
- `pagination.sessionIdParam`: `sessionId`

约束：

- 这个兜底只用于大批量分页明细导出；普通报告、PPT、Word、PDF 和可一次性承载的小表格不使用。
- `url` / `name` 必须来自本次已确认的数据工具，不得猜测。
- `columns` 只声明字段顺序和字段路径；不要补造缺失字段。
- `outputFileName` 只写基础名，不要写目录或时间戳；导出器会自动追加时间戳并避免覆盖。

### 专业版约束

- 专业版只在执行路线判定命中时使用；不要因为内容看起来重要就主动升级。
- 专业版必须按目标格式读取对应 skill，并遵守对应 skill 的生成规则。
- PDF 专业版只接受 `sourcePath` 指向的完整 HTML，禁止传内联 `source`。先按 `pdf` skill 使用 `write` / `edit` 将 HTML 分段写入任务输出目录内以 `.doc-pdf-source-` 开头的临时 `.html` 文件。
- 如果本次任务已经存在完整 `content`，可以原样传入以启用 PDF 覆盖率校验和标准版兜底；不得仅为 PDF 导出重新生成、复述、压缩或改写 `content`。没有可用正文基准时，专业 PDF HTML 至少需要 500 个可见正文字符。
- PDF 临时 HTML 未写完时保留 `<!-- PDF_CONTINUE -->`；所有章节补齐、移除该标记并闭合 `body/html` 后才能导出。不得为了适配单次参数长度而删减章节或压缩正文。
- PDF 专业版成功后临时 HTML 会自动删除；失败时会保留，便于继续使用 `edit` 修复。只有通过 `mode="current"` 或 `content` 取得完整正文时，失败后才允许生成标准版兜底。
- DOCX 专业版按 `docx` skill 使用 `write` / `edit` 将完整 JS 写入任务输出目录内以 `.doc-docx-source-` 开头的临时 `.js` 文件。未完成时保留 `// DOCX_CONTINUE`；移除标记并补齐 `await writeOutput(await Packer.toBuffer(doc));` 后，必须用 `read` 完整自检同一文件，通过后才以绝对路径 `sourcePath` 调用一次 `document_export`。
- DOCX 临时 JS 只读取运行时 `content` 并构造文件，只允许 `require('docx')`。不得引入 `fs/path`、使用 `taskOutputDir`、直接写文件或自行定义 `writeOutput`，不得硬编码整篇报告或重新生成正文。调用时不要传 `source`；成功后临时 JS 自动删除，失败或标准版回退时保留供 `edit` 修复。
- PPTX 专业版按 `pptx` skill 使用 `write` / `edit` 将完整 JS 写入任务输出目录内以 `.doc-pptx-source-` 开头的临时 `.js` 文件。未完成时保留 `// PPTX_CONTINUE`；完成后移除标记，写入唯一的 `// PPTX_EXPECTED_SLIDES: <页数>`，并用 `read` 完整自检同一文件，再以绝对路径 `sourcePath` 调用一次 `document_export`。
- PPTX 临时 JS 只允许 `require('pptxgenjs')`，必须显式输出最终 Buffer。调用时不要传内联 `source`；导出层会检查脚本完整性以及最终 PPTX 的实际页数。成功后临时 JS 自动删除，失败或标准版回退时保留供 `edit` 修复。
- XLSX 专业版继续使用 `source` 传入 JS 编排代码。
- 不要自行运行 `node`、`npm`、`python`、`soffice`、`pandoc` 或 `playwright` 来生成专业版文件。
- 工具返回可修复诊断时，最多按诊断修复一次；不可修复或已生成标准版时，直接交付工具返回文件。

### 中文 PDF 约束

- 只要正文、标题或表头包含中文、日文、韩文，不得默认认为 PDF 一定安全。
- 中文 PDF 必须使用可覆盖 CJK 的字体或已验证的渲染链路。
- 禁止用只覆盖西文字形的默认 PDF 字体直接绘制中文，例如 Helvetica、Times-Roman、Courier。
- 无法确认字体覆盖、字体嵌入或预览渲染正常时，不要把中文 PDF 当作成功交付；优先改为 DOCX，并说明为避免中文乱码已改为 Word 交付。

### 交付约束

- 只有真实文件已生成时，才能说“已导出”。
- 最终文件必须放到应用默认导出目录、任务产出目录或用户明确的交付目录。
- `/tmp` 只能作为临时目录，不能作为最终交付位置。
- 所有最终生成的文档文件底部都必须包含 `内容由AI生成，请仔细甄别`；使用快速导出能力时由导出器自动添加，不要在正文里重复写。
- 导出成功后不要机械重复全文；是否补充摘要或正文由用户意图决定。

### 输出规范

最终回复至少包含：

1. 实际生成的文件格式。
2. 完整文件路径。
3. 文件包含的主要内容。
4. 若有多个文件，说明各自用途。

输出质量要求：

- 先说明导出对象，再说明格式。
- PDF / DOCX 要保留清晰标题层级、日期、数据范围和结论结构。
- XLSX / CSV 要保证字段名稳定、列含义明确。

## 边界

### 进入本技能并执行

- 用户明确要求导出、生成、保存、下载或发送真实文件。
- 用户点名 PDF、Word、Excel、PPT、CSV、Markdown、HTML 等文件格式。
- 用户要求查询、汇总、筛选、改写、整理后生成文件。
- 用户提供内容、markdown、名单、表格、报告或摘要，要求转成文件。
- 用户已经拿到当前报告，要求重新导出、换格式或补充交付格式。

### 进入本技能但先补内容或澄清

- 用户要求查询、汇总、筛选、改写后生成文件，但当前还没有最终正文。
- 用户只给出零散结论，尚不足以形成文件。
- 用户指代“那个报告”“这份材料”但会话里有多个可能对象。
- 导出对象、主体或数据来源不清楚，且无法从本轮上下文确认。

### 不执行文件导出

- 用户只是想在对话里看摘要、结论或报告内容。
- 用户只是询问应该用什么格式。
- 用户要的是内容编排建议，还没有要求真实文件。

### 兜底

- 只有本技能快速导出能力、HTML 路线、对应专业版 skill 都不可用或明确失败时，才允许退回 `scripts/compile_markdown_document.py` 或其他脚本方式生成文件。
