# HTML 生成

## BizOwl 报告导出优先级

如果用户在BizOwl 中要求“查一下并生成 HTML 报告”“转成网页报告”“做成可发送 HTML 文件”，这属于文档导出，不是通用网页设计任务。

HTML 报告优先使用本技能生成美化版单文件 HTML：

1. 先完成必要查询和内容整理，明确用户本次点名的企业、事项、名单或材料。
2. 再基于本次任务最终确认的正文设计完整 HTML 页面，保留标题、章节、表格和结论结构，同时做专业排版。
3. 导出成功后，先明确汇报最终 HTML 文件已生成以及文件路径；在此之后，再根据用户意图决定是否补充摘要或正文说明。

真正开始生成 HTML 文件前，先给用户一句简短预期，例如“开始生成美化版 HTML，预计 1-2 分钟”。若页面很重，可以改成更长区间，但不要承诺精确到秒。

不要调用 `document_export(format="html")`；快速文档导出路径只做常用文档转换，不适合作为 HTML 报告交付。PDF、DOCX、XLSX、PPTX、CSV、Markdown 等其它文档格式仍优先使用 `document-export`。

不要用宽泛线索来猜 HTML 文件来源；标题、文件名、页面主标题和正文主体必须与用户本次请求一致。

所有新生成的 HTML 报告文件底部都必须包含可见提示 `内容由AI生成，请仔细甄别`。此提示仅限于导出的文件本身，不要在聊天消息中附带。

## 快速路径

触发本技能后，直接产出 HTML 交付物。除非用户明确要求解释过程，否则不要在可见回复里输出方案、设计推理或长篇步骤说明。

开始设计前，如果 `../frontend-design/SKILL.md` 可用，读取并遵循它。把 `frontend-design` 当作视觉质量规范，把本技能当作 HTML 交付规范。

## 输出规范

- 生成完整的单文件 HTML，包含 `<!doctype html>`、`html`、`head`、`body`、内联 CSS；需要交互时使用内联 JavaScript。
- 聊天内回复时，默认使用标准 `html` 代码块：

````
```html
<!doctype html>
...
```
````

- 只有在当前宿主明确支持 HTML artifact 标记时，才使用 `artifact:html` 代码块。
- 如果用户要求生成真实文件，把 HTML 写入指定目录；未指定时写入当前工作区。若运行环境提供任务产出目录，最终 HTML 必须放到任务产出目录，不能只留在 `/tmp`。
- 真实文件使用 `.html` 后缀，统一按“简短清晰的标题 + `YYYYMMDD-HHMMSS`”命名，例如 `企业控制关系-20260716-143025.html`；避免使用 `/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 等文件名非法字符。
- 默认写入前先确认目标路径不存在；若同一秒出现同名文件，追加 `-2`、`-3` 等序号。只有用户明确点名要覆盖的已有文件时，才允许覆盖该目标，不得自行猜测或改写其它历史 HTML 文件。
- 默认不要依赖外部 CDN、在线字体或远程脚本。除非用户明确要求框架，优先使用原生 HTML/CSS/JS。
- 默认生成单文件 HTML；如果必须使用图片、字体或其他资产，把资产放在 HTML 文件同级目录或同级 `assets/` 子目录，并使用相对路径引用。
- 最终 HTML 不要留下 `TODO`、`...`、`内容待补充` 等占位内容。
- 只使用本次任务已核验事实。数据不足时，用克制的“暂无数据”状态表达，不要编造关键事实。

## 设计要求

- 遵循 `frontend-design` 的视觉要求：明确字体气质、克制但有辨识度的配色、清晰层级、精细间距和必要的交互细节。
- 根据场景选择界面密度。企业报告、控制关系、股权结构、QCC 分析类页面应专业、紧凑、便于扫读，不要做成营销落地页。
- 使用语义化 HTML、响应式布局、可读的移动端表现和足够的颜色对比度。
- 使用 CSS 变量管理主题色、字体、阴影、圆角和间距。
- 只有在能提升信息表达时才使用内联 SVG，例如控制关系、股权路径、时间线、结构图或数据图示。
- 避免常见 AI 味设计：大面积紫色渐变、空洞装饰光斑、过大的 hero 标题、无意义卡片堆叠、卡片套卡片。

## 降低卡顿感

- 回复重点放在最终 HTML，不要先输出长前言或多套方案。
- 对纯 HTML 格式转换指令，先确认页面主体与用户要求一致；不一致或无法确认时先澄清，不要直接生成。
- 优先生成一个完成度高的版本，不要同时生成多个备选设计。
- 控制 HTML 体量：保留必要样式和交互，避免过长注释、重复 CSS、大段无用脚本。
- 如果内容很多，先做信息分区、摘要卡片和可折叠明细，而不是把全部文字平铺成长页面。
